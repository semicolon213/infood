# AI 고정 응답 — WBS 3.10b

`recommend.json`은 `MockAdapter`의 고정 응답이다. `AI_MOCK=1`이면 v0.3.2 `Recommendation` 스키마로 검증해 반환한다. `AI_MOCK=fail`은 호출 실패를 모의한다. 고정 응답의 ID는 기본 시드 매장에 맞췄다.

API v0.3.2에 따라 기존 메뉴 고정 응답에는 `menuId`와 `reason`만 담는다. 서버는 DB에서 읽은 1인분 전체 레시피를 `consumes`로 채우고 임박 재료를 앞에 배치한다. 이 고정 응답을 검증하려면 [PR #33](https://github.com/semicolon213/infood/pull/33)의 출력 스키마가 필요하다.

참조 ID는 `supabase/seed.sql`의 재료 `30000000-0000-4000-8000-…`·메뉴 `40000000-0000-4000-8000-…`를 쓴다. 문구에는 "오늘", "내일", 현재 보유량 같은 변하는 사실을 확정하지 않는다.

| 항목 | 고정 내용 | 확인할 후속 경로 |
|---|---|---|
| 기존 메뉴 | 된장찌개(메뉴 2), 계란말이(메뉴 6) | 메뉴 ID가 시드와 일치하고 해당 레시피가 시드 재료를 참조 |
| 부족 재료 예제 | 오징어 채소볶음의 오징어 200g | 고정 시드 기준 오징어 입고는 100g. 실제 사용 가능 수량·short 상태는 서버에서 대조 |
| 미등록 예제 | 바질 두부구이의 바질 5, ID=null | 서버 이름 매칭 후 미등록 표시. 바질 없는 기본 시드에서 확인 |
| 단위 | 두부 g, 계란 ea, 간장 ml | 출력 qty는 각 등록 재료의 기본 단위. 환산·원가는 서버 책임 |

응답은 모델 원시 출력이며 `have/short/unregistered`, `availableQty`, `estCost`, `fallback`, 검증 건수를 넣지 않는다. 실제 DB·FEFO·RLS·재고 상태·추천 품질·세 기준별 정렬을 검증한 결과는 아니다.

미등록 재료의 모델 출력에는 단위 필드가 없다. 바질의 qty=5도 확인 전 단위가 확정된 값이 아니며, 조리 단계에서 단위·양을 확인하도록 안내한다. 실제 재료에 연결한 뒤 사용자가 검토해야 한다.

`recommend.test.ts`는 SQL을 실행하지 않고 재료·메뉴 JSON 및 재료 등록·메뉴 등록·레시피 행 각각의 ID 식을 읽어 참조 관계를 대조한다. 오징어 100g 비교는 **입고량 기준**이며 판매·사용·폐기 후 실제 잔량은 검증하지 않는다. DB 실행 검증은 별도다. 기존 보관일수 fixture는 4.6 확장용이며 이 작업에서는 변경하지 않는다.
