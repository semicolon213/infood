# 4.3a 독립 QA 후속 기록

담당: 성윤우 · 2026-11-17 · 기준: 사용자 제공 독립 QA 보고서, 4.3b 병합 `e5c2c87`.

## 대응

| 지적 | 처리 |
|---|---|
| M1 선택 불가 행이 추가를 막음 | 실제로 남은 선택 가능 재료와 빈 선택 대기 행으로 추가 한도를 판단한다. 단종 행은 한도에 넣지 않는다. 단위·브라우저 회귀 검사 추가 |
| M2 대화상자 포커스 복귀 | Esc·취소는 원래 버튼으로, 상태 변경 성공·최신 상태 확인은 상세 제목으로 복귀한다. 상태만 바뀔 때 상세 컴포넌트를 재마운트하지 않는다. 복사창도 복사 버튼으로 복귀 |
| M3 기존 `.env.example` 로컬 변경 | 파일을 읽거나 복원하지 않았다. 기존 사용자 변경을 보존하며 4.3a 패치·검증 소스 동기화·커밋 예정 파일 목록에서 제외한다. `git add -A`는 사용하지 않는다 |
| I1 반올림 표시와 원값 차이 | 화면에서 기본 단위 원값과 기존 formatter의 근삿값을 함께 표시한다. 예: `1,766g (약 1.8kg)`. 복사 정밀도는 기존 계약을 유지하며 소유자 합의 대기 |
| I2 세션 만료 가능성 안내 | 예외로 결과를 확인하지 못한 경우 로그인 만료 가능성과 새 창 로그인 확인을 안내한다. 확정 UNAUTHORIZED와 구분하며 자동 재전송하지 않는다 |
| I3 연결되지 않은 서버 필드 오류 | `id`, 품목 단위, `_` 등 입력란과 연결되지 않는 메시지도 하단 오류 박스에 한국어 위치 설명과 함께 나열한다 |
| I4 날짜 오류의 접근성 연결 | 형식이 잘못된 쪽만 aria-invalid로 표시하고 오류 알림을 aria-describedby로 연결한다. 역전 기간은 양쪽 관계 오류로 표시 |
| I5 계약보다 강한 제약 | 저장 가능한 품목 최소 1개·빈 수량·선택 불가 재료·소수 3자리의 현재 정책은 유지한다. 계약 변경과 리뷰어 합의 없이 완화하지 않는다. 숫자 형식 오류 문구는 예시 중심으로 보완 |
| I6 모두 0일 때 오류 포커스 | 품목 섹션의 실제 오류 문구에 포커스·스크롤을 맞춘다. 고정 버튼에 가리지 않는지 검사 |
| I7 테스트 ID 불일치 | 상태 전이 성공은 IT-ORD-04, 작성중 삭제는 E2E-07 보조로 수정한다. 검증하지 않은 IT-ORD-05·06 통과 라벨은 제거 |
| I8 상태 배지 구분 | 입고완료 배지에 기존 primary 토큰의 옅은 배경·테두리를 적용해 작성중·발주완료와 구분한다. 상태 텍스트도 유지 |
| 초기 입력 경합 의심 | 제출할 때 FormData로 현재 화면 값을 읽어 state와 다르면 표시값을 검증·전달한다. DOM 값과 state 불일치 회귀 검사를 추가했다. 실기기 하이드레이션 경합의 원인·재현 여부까지 규명한 것으로 주장하지 않는다 |

## 검증과 검사 도구

- 깨끗한 소스 복사본에 4.3b upstream 파일과 4.3a 변경만 적용해 검사한다. 원본 `.env*` 값은 복사하지 않는다.
- lint·typecheck 통과, Vitest 205건 통과·90건 건너뜀(로컬 Supabase 없음). 입력 보조 16건 포함.
- 브라우저 보조 검사 17묶음 통과. 375×812, 360×812, 1024×812와 M1·M2 재현·회귀 경로를 포함한다. 실제 서버의 `VALIDATION(fields items.N.ingredientId·memo)`·NOT_FOUND·CONFLICT에 맞춘 화면 처리도 확인했다. 검사 후 3155·54495 포트에 LISTENING 프로세스가 남지 않은 것도 확인했다.
- IT-ORD-08은 담당자 안내대로 g·ml만 판정한다. ea 표기는 합의 대기이며 변경하지 않는다.
- 복사본의 재료 조회 fixture가 원래 `getIngredient` export를 보존하도록 수정했다. 이 사실만으로 production 빌드 통과를 주장하지 않는다.
- 검사 종료 시 자체 실행한 Next.js 프로세스 트리를 정리하고 종료 대기에 제한 시간을 둔다. 다른 개발 서버는 종료하지 않는다.
- 독립 QA 원본의 클라우드 증거 폴더는 이 PC에 없으므로, 이번에 직접 실행한 로컬 증거와 구분한다.

## 남은 확인

1. 로컬 Supabase에서 실제 저장·재조회·수정·삭제·전이, 매장 분리·RLS·RPC와 IT-ORD-01~09 재실행.
2. 실제 인증·refresh 실패와 proxy 경로, 응답 유실 뒤 수동 재저장 중복, iOS·Android date picker 및 초기 입력 경합.
3. I5의 저장 제약·복사 정밀도·ea 표기는 계약 소유자·지정 리뷰어 합의 필요. 배지 대비 수치와 실기기 검사는 별도 확인.
4. 기존 Next.js 보안 업데이트 권고는 별도 범위. 김형균 지정 리뷰·PR 병합 전 완료 체크하지 않는다.
