# 3.2a 메뉴·레시피 화면 검토

- 담당: 성윤우 / 지정 화면 리뷰어: 김형균
- 요구사항: SRS FR-MENU-01~02, UC-03
- 작업 브랜치: `feature/3.2a-menus-ui` (최신 develop에서 분기)
- 상태: 구현·화면 검증 완료, 실제 Supabase 통합·PR 리뷰·병합 대기. `11_TASK.md`는 `[~]` 유지.

## 구현

| 화면 | 동작 |
|---|---|
| `/menus` | 이름·판매가·비활성/특선 상태, 상세 이동, 메뉴 등록, 빈 목록 |
| `/menus/new` | 이름·원 단위 정수 판매가, 재료 선택·추가·삭제, 기본 단위의 1인분 소요량 |
| `/menus/[id]` | 판매가와 레시피 표시, 수정 이동, 확인 후 비활성화 |
| `/menus/[id]/edit` | 저장된 정보·레시피로 시작, 레시피 전체 교체 계약 사용 |

- 조회는 서버 페이지에서 기존 `getMenus`, `getMenu`, `getIngredients`를 호출한다.
- 변경은 기존 `saveMenu`, `deactivateMenu`를 호출하고 성공 후 관련 화면을 갱신한다.
- 문자열 입력을 숫자로 파싱한 뒤 공유 `MenuInput` 스키마로 검증한다. 날짜·단위 환산·원가 계산을 추가하지 않았다.
- 빈 판매가·소요량은 0으로 해석하지 않는다. 재료 중복, 수량 범위, 현재 선택 불가능한 재료를 검사하고 오류를 입력 아래에 표시한다.
- 수정 시 선택할 수 없게 된 재료도 그대로 표시하고 교체/삭제를 안내한다. 자동으로 레시피에서 빼지 않는다.
- 공유 계약대로 0원과 빈 레시피를 허용한다. 빈 레시피는 판매해도 재고가 차감되지 않음을 안내한다.
- 저장 중 폼과 버튼을 잠근다. 실패하면 입력·오류를 유지하고 재시도할 수 있다. 비활성화 확인창에도 취소·실패·재시도를 제공한다.
- 조회 실패, 빈 목록, 잘못된/없는 ID를 구분한다. Next.js 설치 문서에 따라 오류 경계에서 `retry()`를 사용한다.
- 확장 메뉴 원가·원가율·AI 특선 등록은 이번 작업에 포함하지 않는다.
- 독립 QA 후속 수정: 소수 3자리·판매가 상한·지수 표기 검사, 오류의 행별 유지·삭제 후 경로 재배치, DOM 순서의 오류 포커스, 전송 실패 시 새 창 로그인 복구. [항목별 처리](menus-ui-qa-fixes.md) 참고.

## 변경 범위

- `src/app/(main)/menus/`: 목록·등록·상세·수정·로딩·오류·404
- `src/components/menus/`: 목록, 폼·입력 변환, 액션 연결, 상세
- `tests/e2e/menus/check.mjs`: 화면·계약 연결 보조 점검
- `docs/11_TASK.md`, `docs/logs/ai-usage.md`, 이 검토 문서

서버 액션·조회, 공유 계약, DB·마이그레이션, 공통 UI에는 변경이 없다. 기존 `.env.example` 수정은 이번 작업에 포함하지 않는다. 의존성 추가 없음.

### 브라우저 점검 범위

1. 빈 메뉴 목록과 등록 이동
2. 필수값 동시 오류·잘못된 입력의 서버 변경 차단
3. 기본 단위·소수 소요량·중복 재료 선택 방지·0 소요량 거부
4. 네트워크 실패 시 초안 유지와 재시도
5. 등록 요청·저장 중 버튼 잠김·상세 반영·중복 요청 방지
6. 서버 `CONFLICT`의 이름 오류 매핑과 입력 유지
7. 수정 초깃값·재료 삭제·소요량 변경·상세 갱신
8. 비활성화 취소·실패·재시도·비활성 상태
9. 잘못된/없는 ID의 한국어 404·목록 복귀
10. 조회 실패를 빈 목록과 구분하고 재시도
11. 모바일 터치 영역·가로 넘침 및 데스크톱 목록

후속 회귀 8건: 첫 오류 포커스, 오류 유지·행 삭제, 정밀도·상한·지수 표기, 재료 매장/활성/ID 검증, 수정 시 정밀도 전송 차단, 요청 기록 불변성, 등록 중 인증 만료·새 창 로그인·입력 유지·재시도, 비활성화 중 인증 만료·복구.

재현: `node tests/e2e/menus/check.mjs` (별도 dev 서버 불필요).

결과와 이미지는 `test-results/menus-ui-check/`에 생성된다. 이 폴더는 gitignore 대상이다. 인증·PostgREST만 로컬 HTTP fixture로 대체하고 실제 프로젝트의 조회·서버 액션·화면을 실행한다. 실제 Supabase/Auth/RLS 검증이나 전체 E2E-02 통과로 집계하지 않는다. AI는 호출하지 않는다.

## 서버 담당자·리뷰 확인 항목

- `getIngredients`는 3.1b 이전 고정 stub이다. 실제 매장 DB의 재료와 ID가 다르면 서버가 저장을 거부한다. 3.1b 이후 실제 매장 재료로 등록→수정→비활성화를 다시 검증해야 한다.
- 기존 `saveMenu`는 메뉴·레시피를 여러 DB 문장으로 저장한다. 중간 실패 시 부분 반영 가능성이 있다는 주석이 있어, 원자성 여부는 서버 소유자 김형균에게 확인이 필요하다. 3.2a에서는 서버 코드를 수정하지 않았다.
- iOS Safari·Android Chrome 실기기 점검과 지정 리뷰어 승인·PR 병합은 남아 있다.
