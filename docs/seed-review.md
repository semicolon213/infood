# WBS 2.9 가상 데이터 검토

작성: 성윤우 / 2026-11-03. 기준: SRS C-02, `07_DB.md` 8장.

`supabase/seed.sql`은 **2026-11-03 KST 고정 시점**의 로컬 전용 데이터다. 재료 30종, 메뉴 15개·레시피, 10/20~11/02 연속 14일 판매, 직접 사용·폐기 각 3건을 포함한다. 재고는 `receive_stock`, `record_daily_sales`, `record_usage`, `record_waste`만으로 반영하고, 발주 저장도 `save_order`를 쓴다. DB에서 오늘·기한·FEFO를 계산하지 않는다.

| 확인 대상 | 준비한 데이터 |
|---|---|
| 재료 분포 | 채소 10, 육류 5, 수산 4, 유제품·계란 4, 양념 5, 곡류 1, 기타 1(두부) |
| 환산 단위 | 대파 1단=1000g, 계란 1판=30ea, 두부 1모=300g |

고정 UUID를 3.10b mock 응답에서 그대로 참조할 수 있다. 재료 `30000000-0000-4000-8000-000000000001`~`030`, 메뉴 `40000000-0000-4000-8000-000000000001`~`015`이며 번호는 시드의 `n` 순서다. 테스트 이메일은 `demo@jaegokok.example.invalid`, 실제 개인정보·비밀번호는 없다. 로그인 시연은 로컬 메일 수신함에서 매직링크를 열어 확인해야 한다.

남은 조건:

- **2.7 통합 확인 대기:** 2.7의 0001~0003 마이그레이션이 develop에 병합됐다. 선행 테이블·RPC가 없는 환경에서는 시드가 사전 조건 오류로 중단한다. 마이그레이션은 변경하지 않았으며 로컬 `supabase db reset` 및 DB-01~17과의 통합 확인이 필요하다.
- **날짜 연동 대기:** `todayKST()`와 `lib/stock` 함수가 아직 없다. 다른 담당자 함수를 대신 구현하지 않았으며 실행일 기준 상대 날짜 재현은 미완료다. 고정 날짜를 그대로 운영 데이터에 사용하면 안 된다.
- **발주 상태 대기:** 상태 변경은 서버 액션만 허용된다. 액션이 없어 발주 목록 2개를 모두 draft로 준비했다. 액션이 생기면 두 번째를 ordered로 전환해 `07_DB.md`의 draft1·ordered1 조건을 충족해야 한다.
- **Supabase 통합 실행 대기:** 로컬 Docker 스택이 없어 실제 Supabase의 `db reset`은 확인하지 못했다. 아래 임시 PostgreSQL 실행 검증과 구분하며, PR 병합 전까지 2.9를 완료 표시하지 않는다.


정적 검산 결과: 재료30·메뉴15·연속14일, 모든 판매의 레시피 소요량과 고정 계획 일치, 경과 묶음 판매 차감 없음, 차감 후 음수 없음. 최종 잔량 예: 양파9320g·대파4860g·계란70ea·두부5040g. DB 실행 검증을 대신하지 않는다.

## 임시 PostgreSQL 보조 실행 검증

2026-11-03, PGlite 0.5.14 / PostgreSQL 18.6에서 시드 SQL 전체 실행과 보조 검증 7건을 통과했다. 재료30·메뉴15·레시피59·판매 마감14일(판매15행)·입고 묶음31·재고 이동95·직접 사용3·발주2개가 생성됐다. 우유는 전체2700ml·사용 가능0ml·경과2700ml로 조회됐다.

[검증 결과 JSON](seed-validation/report.json) · [다시 실행하는 도구](seed-validation/verify.mjs)

| 보조 검증 | 결과 |
|---|---|
| 실제 0000만 있는 경우 | 명확한 2.7 선행 안내로 중단, 매장 데이터 추가0 |
| 설계서 SQL로 임시 스키마 구성 후 시드 실행 | 전체 SQL 및 내부 개수·판매 계획·잔량/이력 검산 성공 |
| 데이터 수·판매 기간 | 30종·15메뉴·연속14일, 사용3·묶음31 확인 |

| 이력 변경 금지 | 모의 사용자 UPDATE·DELETE 모두0행 |
| 시드 재실행 | 중복 안내로 중단, 기존 재료30종 유지 |

한계: 실제 서버 설정은 PostgreSQL 17인데 이 보조 환경은18.6이다. auth 테이블과 uid 함수도 최소 모의다. 따라서 실제 Supabase Auth·메일 로그인·2.7 마이그레이션·DB-01~17 통합 테스트를 통과한 것으로 표시하지 않는다. 실행일 상대 날짜와 ordered 상태는 여전히 선행 함수/액션 연결 대기다.

재현: 이 작업 브랜치 루트에서, 프로젝트 의존성에 추가하지 않은 PGlite package 폴더를 인자로 준다.

```powershell
node docs/seed-validation/verify.mjs <PGlite-package-directory>
```

기본 결과는 로컬 `.next/seed-validation/report.json`에 기록된다. 별도 도구의 `package.json` 버전과 PostgreSQL 버전, 시드/설계서 SHA-256도 함께 기록한다. [PGlite API](https://pglite.dev/docs/api)의 메모리 DB와 SQL 실행 방식을 사용하며, 실제 DB나 서버 파일을 수정하지 않는다.
추가 미완료 항목: 현재 양념5종·곡류1종·기타(두부)1종으로 양념·곡류 합계는6종이다. `07_DB.md`의 7종 조건과 다르며 데이터 구성과 검증 도구의 분류별 검사를 함께 보완해야 한다. 현재 결과의 success는 보조 검증 7건 통과를 뜻하며 작업 2.9 전체 완료를 뜻하지 않는다.
