# PRD (제품 요구사항 문서)

**제품명(가칭):** 재고콕 — 소상공인용 식자재 재고 관리 및 AI 메뉴 추천 시스템
**버전:** v0.2 / 2026-10-27

---

## 1. 개요

소형 식당·카페 사장님이 **명세서 사진, 바코드 스캔, 하루 판매량 입력**만으로 식자재 재고와 기한을 관리하고, 기한이 임박한 재료를 소진할 **메뉴를 AI로 추천**받는 모바일 우선 웹 서비스.

> "사진 찍고 판매량만 넣으면, 재고와 폐기 위험과 오늘의 메뉴가 정리된다."

## 2. 문제

| 현재 불편 | 원인 | 결과 |
|---|---|---|
| 재고를 기록하지 않음 | 입력이 번거롭고 시간이 없음 | 머릿속·메모장으로 관리 |
| 기한을 놓쳐 폐기 | 입고 묶음별 기한 추적이 안 됨 | 매주 폐기 비용 |
| 남은 재료 활용법을 모름 | 재고와 메뉴가 연결되지 않음 | 같은 재료 반복 폐기 |
| 사용량을 모름 | 판매와 재고 차감이 연결되지 않음 | 감에 의존한 발주 |

## 3. 목표와 성공 지표

| 목표 | 지표 | 목표치 |
|---|---|---|
| 입고 입력 부담 감소 | 명세서 1장 입고 소요 시간 (수동 입력 대비) | 70% 이상 단축 |
| 정확한 자동 입력 | 명세서 인식·재료 연결 정확도 | `10_TEST_PLAN.md` 7.2 목표 충족 |
| 바코드 활용성 | 인터뷰 매장 포장 제품 바코드의 API 조회 성공률 | 측정·보고 (60% 이상이면 핵심 기능 유지) |
| 폐기 감소 | 가상 2주 데이터에서 추천 수용 시 폐기 금액 | 30% 이상 감소 |
| 사용자 반응 | 인터뷰 매장 시연 후 "쓰고 싶다" 응답 | 1곳 이상 |

## 4. 타깃 사용자

**페르소나: 김사장 (42세, 12석 한식당)**
- 직원 1명, 거래처 2곳에서 주 3회 납품, 소스·유제품은 마트에서 수시 구매
- 스마트폰은 능숙, PC는 거의 안 씀
- "재고 앱 써봤는데 입력하다 포기했어요."

**사용 환경:** 주방·창고에서 휴대폰 한 손 조작, 바쁜 시간 외(오전 입고, 마감 후)에 짧게 사용

## 7. 데모 시나리오

1. 아침에 거래처 명세서를 촬영한다.
2. AI가 "양파 10kg, 두부 10모, 계란 30구"를 인식해 기존 재료에 자동 연결한다. 확인이 필요한 줄은 노란색으로 표시된다.
3. 마트에서 산 우유는 바코드를 찍는다. 제품명이 조회되고 "우유"에 연결된다.
4. 품목마다 기한이 계산돼 나온다. 사장님은 두부 날짜만 고치고 입고를 확정한다.
5. 대시보드에 "**두부 D-2, 우유 D-1**" 경고가 뜬다.
6. AI 추천을 누르면 결과가 나온다.
   - **오늘 밀 메뉴:** 순두부찌개 (두부 6모 소진)
   - **신규 특선:** 우유 크림 리조또 (예상 원가 3,200원) → 특선으로 등록
7. 마감 때 판매량을 입력하면 재고가 차감되고 경고와 폐기 예상 금액이 줄어든다.

- 개봉 후 기한 단축
- 네이티브 앱

## 9. 가정과 제약
- 실제 판매 데이터는 확보가 어려워 인터뷰 매장 메뉴 기반 **가상 데이터**를 쓴다.
- 시스템이 계산하는 기한은 **매장 기준 권장 기한**이며 법적 기한이 아니다.
- 바코드는 **제품 단위** 식별이라 개별 포장의 날짜는 알 수 없다. 라벨 인식이나 수동 입력으로 보완한다.
- 식약처 API의 등록 범위와 필드는 인증키 발급 후 확인한다.
