## 1. 문제 정의

소규모 음식점은 식재료 재고를 감각으로 관리한다. 그 결과 아래 문제가 반복된다.

| 현재 불편 | 원인 | 결과 |
|---|---|---|
| 유통기한이 지나 재료를 버림 | 입고 묶음별 기한을 추적하지 않음 | 매주 폐기 비용 발생 |
| 재료가 떨어진 뒤에야 알게 됨 | 판매·사용과 재고가 연결되지 않음 | 품절 메뉴, 급한 추가 구매 |
| 남은 재료 활용법을 모름 | 재고와 메뉴가 연결되지 않음 | 같은 재료를 반복해서 폐기 |
| 발주량을 감으로 정함 | 현재 재고와 적정 재고를 비교할 수단이 없음 | 과다·과소 발주 |

**해결 방향:** 입고·판매·사용 기록으로 재고를 **입고 묶음 단위**로 관리한다. 임박·부족 재료를 한 화면에서 보여 주고, 임박 재료를 소진할 메뉴를 AI로 추천하며, 부족 품목으로 발주 목록을 만든다.

- 사용 환경: 주방·창고에서 휴대폰으로 짧게 사용 (오전 입고, 마감 후 판매 입력)
- 직원은 점주 매장 계정을 함께 사용한다. 직원별 권한 분리는 범위 밖이다.

## 3. MVP 범위

과제 안내서의 필수 기능(F-01~F-05)을 그대로 기능 ID로 쓴다. 상세 요구사항은 요구사항 정의서 3장에 있다.

### 3.1 필수 기능 (5주 안에 반드시 동작)

| ID | 기능 | 재고콕에서의 구현 |
|---|---|---|
| F-01 | 식재료 입고 등록 | 품목·수량·단위·입고일·유통기한 입력. 유통기한을 모르면 재료별 기본 보관일수로 자동 계산 |
| F-02 | 사용·판매 기록에 따른 재고 차감 | 하루 판매량 입력 시 레시피 소요량만큼, 직접 사용·폐기 시 입력량만큼 **기한이 빠른 묶음부터(FEFO)** 차감 |
| F-03 | 임박·경과·부족 표시 | 대시보드에 D-3 이내 임박, 기한 경과, 최소 재고 미만 품목 표시 |
| F-04 | AI 메뉴·레시피 추천 | 임박 재료를 소진할 기존 메뉴와 신규 특선 제안. 필요 재료마다 실제 재고 DB와 대조해 **보유/부족** 표시 |
| F-05 | 부족 품목 기반 발주 목록 | 최소 재고 미만 품목의 권장 발주량을 계산하고, 수정·저장·복사 |

필수 기능을 동작시키려면 **재료 관리**(단위·최소 재고·기본 보관일수), **메뉴·레시피 관리**(소요량), **로그인·매장 분리**가 함께 있어야 한다. 이 세 가지도 필수에 포함한다.

### 3.2 확장 기능 (필수 기능 완성 후 선택)

| 순서 | 기능 | 착수 조건 |
|---|---|---|
| 1 | 실사 보정, 주간 폐기 금액 | 13주차 점검에서 F-01~F-05 동작 |
| 2 | 메뉴 원가·원가율 계산 | 위와 같음 |
| 3 | AI 재료 보관일수 추천 | 위와 같음 |
| 4 | **AI 명세서 사진 입고** — 거래명세서 사진에서 품목·수량·단가를 읽어 확인 후 입고 | 13주차 점검 통과 + 1~3 완료 |

14주차(11/24)에 기능을 동결하므로, 그때까지 끝나지 않은 확장 기능은 결과보고서의 "향후 과제"로 넘긴다.

### 3.3 범위 밖

바코드 스캔, 식약처 등 공공 API 연동, 포장 라벨 날짜 인식, 축산물 이력 연동, POS 연동·결제, 거래처 자동 발주(전송), 수요 예측, 알림(카카오톡·푸시), 여러 매장·직원별 권한, 네이티브 앱

## 4. 차별성

과제 안내서의 유의사항대로, 부교재 「냉장고를 부탁해」 실습과 달리 **매장 운영 관점**의 설계를 중심에 둔다.

| 「냉장고를 부탁해」 유형 | 재고콕 |
|---|---|
| 재료 목록만 보고 레시피 추천 | **입고 묶음별 기한·잔량** 추적 |
| 재고 차감 없음 | 판매량 입력 시 **레시피 기반 FEFO 자동 차감** |
| 폐기·발주 개념 없음 | **폐기 기록**과 **부족 품목 발주 목록** |
| AI 결과를 그대로 표시 | AI 추천 재료를 **실제 재고와 대조**해 보유/부족 표시, 사용자 확인 후에만 반영 |

## 5. 생성형 AI 활용과 검증 장치

| AI 기능 | 역할 | 검증 장치 |
|---|---|---|
| 메뉴·레시피 추천 (F-04, 필수) | 임박 재료를 소진할 메뉴와 조리 아이디어 생성 | ① 출력 형식을 스키마로 강제 ② 추천 재료·메뉴를 재고 DB와 대조해 보유/부족·미등록 표시 ③ 원가·수량은 AI가 아닌 서버 코드로 계산 ④ "AI 추천" 표시, 사용자가 등록해야 메뉴에 반영 |
| 명세서 사진 입고 (확장) | 사진에서 품목·수량·단가 추출 | 확인 화면에서 사용자가 수정·확정해야 재고에 반영. 정답 데이터로 인식 정확도 측정 |

검증 결과(추천 검증 통과율, 보유/부족 표시 정확도)는 13주차 테스트 결과표와 최종 AI 활용 검증 보고서에 기록한다.
