# WBS 3.1a 재료 화면 검토

작성: 성윤우 / 갱신: 2026-11-06. FR-ING-01~03·05, BR-03·05, NFR-05.

`feature/3.1a-ingredients-ui`의 기존 화면을 `develop` 6987036의 공유 계약·조회·서버 액션에 연결했다. 변경 범위는 재료 페이지·재료 컴포넌트, 해당 테스트·화면 기록과 본인 작업 로그다. `actions/ingredients.ts`, `lib/queries`, `types/contracts.ts`, 공통 UI·레이아웃·인증·DB는 수정하지 않았다. 새 의존성은 없다.

## 구현

| 경로 | 동작 |
|---|---|
| `/ingredients` | 서버 컴포넌트에서 `getIngredients({q,status})` 조회. 검색 제출·임박/지남/부족·보관 필터를 URL에 반영하고 새로고침·뒤로가기로 복원. `/ingredients?status=low` 직접 진입 지원 |
| `/ingredients/new` | 공유 `IngredientInput`으로 검증한 DTO를 `createIngredient`에 전달. 성공 시 목록으로 복귀. `?returnTo=/receive`일 때만 입고로 복귀 |
| `/ingredients/[id]` | UUID·조회 결과 확인, 전체/사용 가능/경과 재고 구분, 서버가 정렬한 묶음의 입고일·기한·잔량·단가·계산 근거, 묶음 폐기 링크 |
| `/ingredients/[id]/edit` | 기존 값·한국어 카테고리·환산 단위를 채우고 `updateIngredient` 호출. 성공 시 상세로 이동·갱신 |
| 상세 비활성화 | 경과 포함 `totalRemaining > 0`이면 차단. 잔량이 없으면 확인창 후 `deactivateIngredient` 호출. 실패는 확인창 안에 표시하고 성공 시 목록으로 이동 |
| `/ingredients/preview` | 기존 개발용 가상 데이터 미리보기 유지. 개발 환경·로그인 제한, 저장 없음, 운영에서는 not-found |

조회 실패와 결과 0개를 구분하고 재시도·필터 초기화를 제공한다. 폼의 서버 오류는 필드에 표시하고 입력은 유지한다. 입력을 고치면 해당 필드의 이전 오류를 지우며, 저장 중과 성공 후 화면 이동 중에는 입력·저장 버튼과 중복 요청을 막는다. 환산 단위는 최대 10개이며 예약 이름·중복·양수 등은 공유 계약을 따른다. 기한 추적을 끄면 숨긴 보관일수는 전송하지 않는다.

날짜·재고 합계·FEFO·단위 환산·원가는 화면에서 계산하지 않는다. 서버의 `daysLeft`, 재고 집계, `isLow`를 표시하며 수량은 소수 3자리, 단가는 4자리까지 표기한다. 목록에서 기한이 없다는 이유만으로 추적 제외라고 단정하지 않는다. 상세는 `trackExpiry`를 따른다. 색상은 기존 디자인 토큰과 shadcn/ui를 사용한다.

## QA 지적 조치 (11/06)

- **1·2**: 상세 묶음에 목록과 동일한 기한 배지를 적용했다. D-0~1은 빨강 테두리, D-2~3은 주황이다. 잘못된 ID와 없는 UUID의 상세·수정 경로는 한국어 안내와 재료 목록 복귀를 제공한다.
- **3·4**: 숫자 변환 오류와 공유 계약 오류를 함께 수집한다. 정수 검증 실패가 다른 필드·중복 단위 검증을 막지 않게 했다. 음수 재고는 0 이상 안내를 표시한다. 환산 단위 삭제는 다른 필드 오류를 유지한다.
- **5·6**: 이 화면의 비활성화 확인창에서 공통 X 버튼을 숨기고 기존 44px 취소 버튼을 사용한다. 저장 바에 하단 안전 영역 높이를 반영했다. iPhone 실기기 확인은 남아 있다.
- **7**: 화면 단위 테스트는 `UI-ING-UNIT`, stub 기반 브라우저 점검은 `UI-ING-BROWSER`라는 로컬 접두어를 사용한다. `10_TEST_PLAN.md`의 공식 `IT-ING-01~07`·`E2E-02`를 통과한 것으로 집계하지 않는다. 테스트 계획의 정식 대응 관계는 임지섭 검토 시 합의한다.
- **8·9**: AI 활용 로그를 8열·기존 날짜 형식으로 정리했다. 문서 스크린샷은 화면 맨 위에서 다시 촬영하고, 촬영 중에만 Next 개발 표시를 숨긴다. 전체 페이지 촬영 중에는 고정 상단바·저장 바·하단 메뉴를 문서 흐름에 놓아 콘텐츠를 가리지 않게 한다. 공통 UI·Next 설정은 변경하지 않는다.
- 이전 QA에서 누락된 `[id]/edit/page.tsx`도 로컬에서 직접 읽었다. UUID 검사·비동기 params·조회 예외 처리·초깃값·기본 단위 잠금·서버 액션 연결을 확인했다.

## 남은 일과 서버 담당자 확인

1. **3.1b 실제 DB 구현**: 현재 조회는 고정 fixture, 변경 액션은 성공/오류만 반환한다. 등록·수정·비활성화 후 데이터가 유지된다는 검증은 하지 않았다. 새로 생성한 stub ID는 상세 조회에 없으므로 등록 성공 시 목록으로 이동한다. 실제 서버 연결 후 저장·재조회·매장 격리 E2E를 별도로 확인해야 한다.
2. **기본 단위 변경 기준**: 반환된 `lots`는 잔량>0인 묶음만 포함한다. 화면은 남은 묶음이 확인될 때 미리 잠그고, 그 외에는 서버의 `CONFLICT` 판정을 따른다. 과거 묶음까지 변경을 금지할지는 현재 계약만으로 확정할 수 없으므로 3.1b 담당자 확인이 필요하다. 과거 이력이 없다고 추측하지 않는다.
3. **입고 화면 연계(PR #17, 김형균)**: `/ingredients/new?returnTo=/receive` 진입·복귀는 준비했다. 입고 폼에서 이 경로를 사용하고 기존 입력을 유지하는 작업은 입고 담당자 범위다. 관련 파일은 수정하지 않았다.
4. **목록 기한·임박 정보**: `IngredientSummary`에는 `trackExpiry`가 없어 목록에서는 기한 정보 없음으로 표시한다. 상세는 정확히 구분한다. 조회 stub은 가장 빠른 기한만 보고 임박 필터를 적용해 경과 묶음과 D-1 묶음이 함께 있는 두부를 제외한다. API의 "임박 묶음 있음" 기준과 차이가 있으므로 3.1b에서 확인해야 한다. 실서버가 두부를 반환해도 현재 목록 DTO로는 경과 배지와 임박 여부를 함께 알릴 수 없다. 화면에서 결과를 다시 거르거나 계약 필드를 임의로 추가하지 않았다.
5. **PR 검토·병합**: 화면 김형균, 서버 연결·테스트 임지섭 검토가 필요하다. 지정 리뷰어의 승인 후 병합하며, PR 병합 전에는 `11_TASK.md`의 `[~]`를 유지한다.
6. **환산 단위 대소문자**: 공유 계약은 `Box`와 `box`의 중복을 허용한다. DB 제약·입고 매칭 기준과 함께 서버 담당자 확인이 필요하다. 화면에서 독자적인 규칙을 추가하지 않았다.
