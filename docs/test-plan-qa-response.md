## 검증과 다음 단계

- 기존 184개 ID는 보존하고 UT-UNIT-08·IT-USE-10을 추가해 186개 정의다. 구조 점검은 의미 정확성의 증거로 사용하지 않는다.
- 공통 fixture: 사용 가능 1000g, 경과 500g, 총 1500g, 권장 발주 600g. 판매 12인분은 1000g 차감·부족 200g이다.
- 충돌 설계: DB-09 실패 후 P=500/Q=250, DB-11 한쪽 성공 후 P=400/Q=200, 재계획 성공 P=400/Q=0·부족 Q=50, 두 번째 충돌 후 P=500/Q=150이다. 이는 문서의 손계산이며 실제 트랜잭션 실행 증거는 아니다.
- 수정 후 구조 검사·공통 검사 기록은 `test-results/test-plan-3.9/after-qa/`에 둔다. 원래 독립 QA 폴더는 수정하지 않는다.
- 수정 후 구조 점검 10건 통과, 184개 기존 ID 문자열 보존·2개 추가를 확인했다. 별도 계산과 근거 발췌는 review-evidence.json에 기록했다. Node24 격리 소스 183파일에서 lint·typecheck 통과, Vitest 96건 통과·24건 건너뜀이다. 이 결과는 계획 케이스의 실제 DB 실행이나 독립 재검토 통과를 뜻하지 않는다.
- 다음 단계는 수정본 독립 재검토, 10.2의 담당자 확인·합의, 임지섭 승인·PR 병합이다. 실제 DB·통합·브라우저·AI 평가는 4.4 실행 단계에서 기록한다.
