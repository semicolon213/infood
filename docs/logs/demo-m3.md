# 12주 중간 데모 (11/10 3교시, 5분) — WBS 3.11

> 작성: 김형균 · 시연: 김형균(진행), 임지섭(서버·DB 질문), 성윤우(화면 조작)
> 환경: Vercel 운영 배포 + 클라우드 Supabase(마이그레이션 0001~0003 적용, 시드 없음). 휴대폰 화면 비율(375×812)로 띄운다.

## 1. 시연 순서

| 시간 | 화면 | 보여 줄 것 | 말할 것 |
|---|---|---|---|
| 0:00~0:40 | (발표) | 문제와 목표 | "소형 식당은 유통기한·재고를 종이로 관리한다. 재고콕은 묶음(입고 단위)별 기한으로 먼저 쓸 재료를 알려 주고, 남은 재료로 만들 메뉴를 AI가 추천한다." |
| 0:40~1:10 | 로그인 → 매장 만들기 | 매직링크 로그인, 매장 생성 후 빈 홈 | 매장은 세션에서만 구한다(클라이언트 값 불신). 모든 테이블에 매장 격리 RLS |
| 1:10~2:20 | 재료 등록·목록 | 양파(g, 냉장, 기본 보관 7일, 환산 단위 "망 = 15000g") 등록 → 같은 이름 재등록 시 "같은 이름의 재료가 있어요" → 목록 검색·필터 | **DB 연동 기능 ①.** 입력 검증(Zod), 오류 문구 규칙, 기본 단위는 재고가 생기면 잠김 |
| 2:20~3:20 | 메뉴·레시피 | 양파볶음 메뉴 등록, 1인분 소요량(양파 150g) → 목록 | **DB 연동 기능 ②.** 레시피 소요량이 판매 마감 때 재고 차감 기준이 된다 |
| 3:20~4:10 | 입고 · 판매 마감 화면 | 여러 품목 입고(기한 자동 계산과 근거 표시), 판매 마감에서 부족 경고 | 화면은 완료, 서버(입고 RPC·FEFO 차감)는 13주 첫 작업. 차감 규칙은 BR-02(기한 빠른 묶음부터, 경과 묶음 제외) |
| 4:10~5:00 | (발표) | 설계 요점, 다음 주 계획 | 패턴 2개: Adapter(AI SDK를 `AiClient`로 감쌈 → 테스트는 Mock), Strategy(추천 기준 교체). 13주: 입고·판매 서버, 대시보드, AI 추천 |

## 2. 준비물·확인 (시연 전)

- [ ] Vercel에서 로그인 메일이 오는지 (Supabase 메일 발송 제한 주의: 같은 주소로 여러 번 보내지 않기, 미리 로그인해 둔 탭 준비)
- [ ] 재료·메뉴 화면이 오류 없이 열리는지 (클라우드 DB 마이그레이션 적용 후 첫 확인)
- [ ] 데모 계정의 매장에 재료 3~4개를 미리 등록해 두기 (목록·필터가 비어 보이지 않게)
- [ ] 실패 대비: 로컬 개발 서버 화면 녹화 또는 스크린샷

## 3. 예상 질문

| 질문 | 답 |
|---|---|
| AI가 틀린 재고를 말하면? | AI 출력은 사용자 확인 없이 DB에 반영하지 않고(BR-04), 추천 재료는 서버가 실제 재고와 다시 대조해 보유/부족/미등록으로 표시한다 |
| 동시에 두 기기에서 판매를 마감하면? | 차감은 RPC 한 트랜잭션에서 묶음을 잠그고(FOR UPDATE) 잔량을 다시 확인한다. 바뀌었으면 `STOCK_CONFLICT`로 한 번 다시 계획한다 (06 15장 QS-1) |
| 왜 입고·판매가 아직 저장이 안 되나? | 화면↔서버 계약(2.10)을 먼저 정해 화면과 서버를 병렬로 만들었다. 서버(3.3b·3.6b)가 13주 첫 작업이고, 화면은 계약 그대로 연결된다 |
