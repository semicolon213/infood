# 12주 중간 데모 (11/10 3교시, 5분) — WBS 3.11

> 작성: 김형균 · 시연: 김형균(진행), 임지섭(서버·DB 질문), 성윤우(화면 조작)
> 환경: Vercel 운영 배포(`main` = `release/m3`, PR #39) + 클라우드 Supabase(마이그레이션 0001~0003 적용, 시드 없음). 휴대폰 화면 비율(375×812)로 띄운다.
> 시연 배포에 들어간 서버: 재료(3.1b)·메뉴(3.2b)·**입고(3.3b, #32·#38)**. 판매 마감·사용·폐기 서버(3.6b·3.7b)는 release 이후 병합돼 시연 배포에는 없고 화면은 stub 응답이다.

## 2. 준비물·확인 (시연 전)

- [ ] Vercel에서 로그인 메일이 오는지 (Supabase 메일 발송 제한 주의: 같은 주소로 여러 번 보내지 않기, 미리 로그인해 둔 탭 준비)
- [ ] 재료·메뉴 화면이 오류 없이 열리는지 (클라우드 DB 마이그레이션 적용 후 첫 확인)
- [ ] 데모 계정의 매장에 재료 3~4개를 미리 등록해 두기 (목록·필터가 비어 보이지 않게). 단 첫 등록으로 보여 줄 **양파는 미리 등록하지 않았는지** 확인
- [ ] 계정 두 개 구분: 로그인·매장 생성 시연용(매장 없는 새 계정)과 재료가 준비된 계정의 미리 로그인한 예비 탭. 매장이 있는 계정은 매장 생성 단계가 생략된다
- [ ] 실패 대비: 로컬 개발 서버 화면 녹화 또는 스크린샷

## 3. 예상 질문

| 질문 | 답 |
|---|---|
| AI가 틀린 재고를 말하면? | AI 출력은 사용자 확인 없이 DB에 반영하지 않고(BR-04), 추천 재료는 서버가 실제 재고와 다시 대조해 보유/부족/미등록으로 표시한다 |
| 동시에 두 기기에서 판매를 마감하면? | 같은 날짜면 하루 한 번만 마감할 수 있어서 한쪽은 "이미 마감한 날짜"(`CONFLICT`)로 거부된다. 다른 날짜끼리 같은 묶음을 동시에 차감하면, RPC가 한 트랜잭션에서 묶음을 잠그고(FOR UPDATE) 잔량을 다시 확인해서 바뀌었으면 `STOCK_CONFLICT`로 거부하고, 서버가 최신 재고로 한 번 다시 계획한다 (06 15장 QS-1, 3.6b에서 구현·병합) |
| 왜 판매 마감은 아직 저장이 안 되나? | 화면↔서버 계약(2.10)을 먼저 정해 화면과 서버를 병렬로 만들었다. 입고 서버(3.3b)는 시연 배포에 들어갔고, 판매·사용·폐기 서버(3.6b·3.7b)는 11/10 병합돼 다음 배포에 들어간다. 화면은 계약 그대로라 바꿀 것이 없다 |
