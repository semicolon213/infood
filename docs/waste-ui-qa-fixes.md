# 3.7a 독립 QA 후속 수정

기준: 사용자가 제공한 D-1~D-7 보고서. 원본 `test-results/waste-independent-qa/`는 보존한다. 변경은 성윤우의 사용·폐기 화면·테스트·검토 문서 범위다.

| 항목 | 수정과 회귀 검증 |
|---|---|
| D-1 폐기량·사유 덮어쓰기 | 직접 묶음을 고르면 대상 ID만 바꾸고 입력한 수량·사유·메모를 유지한다. 경과 묶음 링크로 처음 진입할 때에만 잔량 전체·기한 경과를 채운다. 일반 묶음 링크의 수량·사유는 빈 값으로 시작한다. 양파 10g·변질 입력 후 5,000g 묶음 선택 시 그대로 유지됨을 확인했다. |
| D-2 결과 가시성·포커스 | 성공 결과에 포커스를 옮기고 고정 헤더 아래로 스크롤한다. 사용 부족 경고·폐기 잔량 결과가 헤더와 저장 바 사이에 들어오는지 좌표로 검사했다. 글꼴 로딩 이후 검사하고 스크린샷 촬영 후에도 다시 검증한다. |
| D-3 인증 만료 후 기록 새로고침 | 전송 예외 안내에서 원래 창의 `router.refresh()`를 제거했다. 기록 확인은 새 창으로 열고 인증이 만료되어 새 창이 로그인으로 이동해도 원래 입력은 남는다. 새 창 로그인 후 원래 폼의 재시도를 확인했다. |
| D-4 부족 안내 조사 | 이름 뒤에 조사를 붙이지 않고 “계란 재고가 10ea 부족했어요”로 표시한다. 받침 있는 이름을 액션 응답에 넣어 확인했다. |
| D-5 재료 변경 시 메모 유실 | 재료 변경 시 메모·사유를 유지한다. 기본 단위가 바뀔 수 있어 묶음·수량만 초기화한다. 계란 묶음을 다시 골라도 잔량 전체는 채우지 않는다. |
| D-6 NOT_FOUND 복구 | 최신 재료·묶음을 다시 받을 수 있는 재고 새로고침 버튼을 제공한다. 응답 모의와 새로고침 후 메모·수량 유지로 확인했다. |
| D-7 기존 검사·이미지 한계 | 고정 헤더·저장 바·하단 탭을 static으로 바꾸는 처리를 제거했다. 실제 375×812 뷰포트와 현재 스크롤로 촬영하고, D-1~D-6 회귀·실제 결과 좌표 검사를 추가했다. |

## 검증

- 수정 소스의 lint 오류·경고 0건, 타입 검사·프로덕션 build 통과.
- Vitest **109건 통과·24건 건너뜀**, 이번 화면 입력·오류 상태 보조 검사 **13건** 포함.
- 브라우저 **16개 흐름 통과**. 부족·NOT_FOUND·충돌은 액션 응답 모의, 인증·매장은 로컬 HTTP fixture다. 실제 DB 변경 검증과 구분한다.
- 결과 레이아웃 증거: `test-results/waste-ui-check/result.json`의 `resultLayouts`. 실제 고정 바와 결과의 포커스·좌표를 확인한다.
- 화면·컴포넌트 11개 소스의 원본/검증 복사본 SHA-256을 다시 대조했다. 기존 메뉴 QA 임시 파일 때문에 전체 타입 검사가 오염되는 문제는 원본 보존·소스 복사본 검증 방식으로 분리했다.

이전 QA 자료는 삭제하지 않는다. 영구적인 환경 정리는 프로젝트 공통 tsconfig에서 `test-results`를 제외하는 방향을 권장하며, 이번 화면 작업에서는 공통 설정을 변경하지 않았다.

화면 관련 D-1~D-7을 조치했으며, 실제 Supabase·FEFO·RLS·이력 영속화·멱등성은 여전히 3.1b·3.7b 검증 범위다. 지정 리뷰어 승인·PR 병합은 남아 있다.
