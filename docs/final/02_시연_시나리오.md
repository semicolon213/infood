# 시연 시나리오와 시연 위험 관리 — 재고콕

> WBS 5.5 · 작성 김형균 · 최종 발표(12/01) 시연 3분, 시연 영상(WBS 5.6, 3분 이내)도 같은 순서로 찍는다.
> 기준: `docs/01_PRD.md` 7장 데모 시나리오를 실제 구현(11/24 develop `a90f20c`, 확장 4.5~4.8 포함)에 맞춰 고쳤다. 필수 F-01~F-05 흐름을 중심으로 하고, 확장 기능은 시간이 남을 때만 보여 준다.
> 환경: Vercel 운영 배포(`main`) + 클라우드 Supabase + Google Gemini(무료 등급). 휴대폰 화면 비율 375×812.

## 1. 사전 준비 (발표 전날·당일 오전)

| # | 할 일 | 확인 방법 | 담당 |
|---|---|---|---|
| 1 | 클라우드 Supabase가 켜져 있는지 확인 (무료 플랜은 사용이 없으면 일시 정지됨, 11/17 실제 발생) | Supabase 대시보드 상태 ACTIVE, 운영 URL 로그인 화면이 뜸 | 김형균 |
| 2 | 시연 계정 2개: ① 시연용(재료·메뉴 준비됨) ② 예비(같은 데이터) — 둘 다 **미리 로그인한 탭**을 열어 둔다. 매직링크 메일 지연에 대비 | 두 탭에서 대시보드가 열림 | 김형균 |
| 3 | 시연 데이터: 재료(두부·양파·대파·돼지고기 앞다리 등)와 메뉴(순두부찌개·제육볶음)를 등록, 대파는 최소 재고보다 적게 | 대시보드에 "대파 부족" | 김형균 |
| 4 | **입고할 두부·양파는 미리 입고하지 않는다** (첫 입고를 보여 주기 위해) | 재료 상세 묶음 없음 | 김형균 |
| 5 | 그날 판매 마감을 아직 하지 않았는지 확인 (같은 날짜는 한 번만 마감됨) | 판매 마감 화면에 마감 기록 없음 | 김형균 |
| 6 | AI 추천 1회 미리 호출해 Gemini 응답 확인 (무료 등급 한도·지연 확인) | 추천 결과에 "AI 추천" 표시, 15초 이내 | 김형균 |
| 7 | 시연 영상 파일을 발표 PC 바탕화면과 USB에 둘 다 저장 | 오프라인 재생 확인 | 성윤우 |
| 8 | 발표 PC 화면 배율·브라우저 확대(휴대폰 비율 375×812 개발자 도구) 미리 맞춤 | 하단 탭이 화면에 다 보임 | 김형균 |

## 2. 시연 순서 (3분)

| 시간 | 화면 | 조작 | 말할 내용 (한 문장) | 보여 줄 요구사항 |
|---|---|---|---|---|
| 0:00~0:35 | 입고 | 두부 10모(기한 직접 입력, 내일), 양파 10kg(kg 입력 → g 자동 환산, 기한은 기본 보관일수로 자동) → 저장 | "두부는 기한을 직접 넣고, 양파는 기본 보관일수로 기한이 자동 계산됩니다" | F-01, BR-01·03 |
| 0:35~0:55 | 대시보드 | 홈 탭 | "두부가 D-1 임박, 대파가 부족으로 떠요" | F-03, BR-05 |
| 0:55~1:45 | AI 추천 | 기준 "유통기한 우선" → 추천 받기 | "재료 옆 보유·부족·미등록 표시는 AI가 아니라 서버가 실제 재고와 대조한 결과예요. 원가도 서버가 계산해요" | F-04, BR-04, FR-REC-03 |
| 1:45~2:05 | 특선 등록 | 신규 특선 [수정해서 등록] → 판매가 입력 → 등록 | "AI 결과는 사람이 확인한 뒤에만 메뉴가 돼요" | FR-REC-07, BR-04 |
| 2:05~2:35 | 발주 | 발주 탭 → 새 목록 (대파 권장량 채워짐) → 수량 수정 → 저장 → 복사 | "부족한 대파는 권장 발주량이 미리 채워져 있고, 복사해서 거래처에 보내요" | F-05, BR-06 |
| 2:35~3:00 | 판매 마감 → 대시보드 | 순두부찌개 3그릇 입력 → 마감 → 홈 | "기한이 빠른 묶음부터 줄어서 두부 임박 경고가 줄었어요" | F-02, BR-02 |

**시간이 남을 때만 (선택)**
- 폐기 기록: 대시보드 "지남" → 폐기 처리 링크 → 수량 자동 입력.
- 명세서 사진 입고(4.7): 거래명세서 사진 → AI가 품목·수량 추출 → 확인 화면에서 고친 뒤 입고. AI 결과는 확인 후에만 저장된다는 점을 다시 강조.
- 주문별 판매(4.8): `/sell`에서 메뉴 1건 판매 → 그 자리에서 재고 차감. **시연 계정의 같은 날짜에 판매 마감과 섞어 쓰지 않는다**(리허설에서 동작 확인 전까지).

## 3. 시연 위험 관리

| 위험 | 가능성 | 영향 | 예방 | 발생 시 대응 |
|---|---|---|---|---|
| Supabase 일시 정지·장애 | 중 (11/17 실제 발생) | 로그인·조회 전부 실패 | 발표 전날·당일 오전 접속해 ACTIVE 확인 (1장 #1) | 즉시 시연 영상으로 전환 |
| Gemini 거부(403)·한도 초과(429)·지연 | 중 (11/17 새 키에서 403 발생) | AI 추천 결과 대신 규칙 기반 대체 | 당일 1회 미리 호출 (#6) | **앱이 자동으로 규칙 기반 대체 추천을 보여 줌** → "AI가 실패해도 서비스는 멈추지 않는다"는 설계(NFR-08)로 설명하고 진행 |
| 매직링크 메일 지연 | 중 | 로그인 못 함 | 미리 로그인한 탭 2개 (#2) | 예비 탭으로 진행 |
| 같은 날짜 판매 마감 중복 | 중 (리허설 때 마감하면 발생) | "이미 마감한 날짜" 거부 | 리허설은 예비 계정으로, 시연 계정은 당일 마감 금지 (#5) | 예비 계정으로 전환 |
| 강의실 네트워크 불안정 | 중 | 화면 로딩 지연·실패 | 휴대폰 핫스팟 준비 | 시연 영상으로 전환 |
| 시연 데이터가 리허설로 바뀜 | 중 | 대시보드 표시가 대본과 다름 | 리허설 뒤 데이터 다시 준비 (#3·#4) | 화면에 보이는 대로 설명하고 진행 |
| 시간 초과 | 중 | 발표 뒷부분 잘림 | 단계마다 한 문장만 말함, 폐기는 선택 | 발주 복사·폐기를 건너뛰고 판매 마감으로 |
| 발표 PC 브라우저 확대 문제 | 하 | 하단 탭이 안 보임 | 미리 맞춤 (#8) | 개발자 도구 기기 모드로 전환 |
| 시드 데모 계정으로 로그인 불가 (이슈 #92, 11/24 열림) | 상 (시드 계정을 쓸 경우) | 시연 계정 로그인 실패 | 시연 계정은 시드가 아니라 **실제 가입한 계정**에 데이터를 직접 등록 (#2·#3) | 예비 탭으로 진행 |
| 마감·주문별 판매를 같은 날짜에 함께 사용 | 중 | 예상과 다른 차감·거부 | 시연에서는 판매 마감만 사용, `/sell`은 선택 시연으로 다른 계정에서 | 선택 시연 생략 |

**전환 기준:** 한 단계에서 15초 넘게 진행이 안 되면 망설이지 않고 시연 영상으로 바꾼다. 영상은 이 문서 2장과 같은 순서라 말할 내용은 그대로 쓴다.

## 4. 시연 영상 촬영 기준 (WBS 5.6)

- 3분 이내, 2장 순서 그대로. 자막으로 단계 이름과 요구사항 ID를 넣는다.
- 실제 Gemini 응답이 나온 화면을 쓴다. 규칙 기반 대체 화면을 쓸 때는 "AI 실패 시 대체"라고 자막으로 밝힌다.
- 시연 계정의 이메일 주소가 화면에 나오지 않게 가린다.
