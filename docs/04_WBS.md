**프로젝트:** 재고콕 (PBL 후보 과제 6)
**기간:** 2026-10-27 ~ 2026-12-01, 1주 스프린트 5회(10~14주) + 최종 발표(15주)

| 이름 | 운영 역할 | 개발 담당 | 맡는 코드 영역 |
|---|---|---|---|
| 김형균 | 팀장(PM) | 핵심 화면 · AI 계층 | 앱 골격·공통 UI, 입고·판매 마감·대시보드·추천 화면, `lib/ai` (Adapter·Strategy·추천 API) |
| 임지섭 | 설계·문서 | 백엔드·DB · 계산 | DB·RLS·RPC, `lib/stock` 계산 함수 전부, 서버 액션·조회, 인터페이스 계약 |
| 성윤우 | 검증 | 관리 화면 · 테스트 | 재료·메뉴·사용폐기·발주 화면, 화면 흐름도, 프롬프트 초안·mock 응답, 가상 데이터, 테스트 실행 |

> **배치 원칙:** 정확성 목표(NFR-01)가 걸린 계산·트랜잭션과 과제 차별점인 AI 추천·재고 대조는 김형균·임지섭이 맡는다. 성윤우는 범위가 분명하고 결과를 바로 확인할 수 있는 화면과 검증 업무를 맡되, 본인 이름이 걸린 기능(F-01 재료, F-02 사용·폐기, F-05 발주 화면)을 가진다.
> 공수 단위는 **인·일**이며, 1인·일은 약 4시간 작업이다. 화요일 수업(1인·일)과 주중 작업을 합쳐 1인당 주 3~4인·일을 기준으로 잡았다.
> 담당자가 두 명이면 두 사람이 각각 그만큼 쓴다. "전원"은 세 명이 각각 그만큼 쓴다. 요구사항 ID는 ② 요구사항 정의서를 따른다.
> 작업 ID 끝의 **a = 화면, b = 서버**다. 같은 기능의 a·b는 2.10 계약을 기준으로 동시에 진행한다 (3장).

## 3. 병렬 작업 규칙

세 명이 같은 주에 동시에 작업해도 서로 기다리거나 같은 파일을 고치지 않도록 다음을 지킨다.

### 3.1 코드 소유권

한 파일은 한 사람만 고친다. 다른 사람의 파일을 바꿔야 하면 소유자에게 PR 리뷰 요청이나 이슈로 부탁한다.

| 소유자 | 폴더·파일 |
|---|---|
| 김형균 | `app/(main)/layout.tsx`, `app/(main)/page.tsx`(대시보드), `app/(main)/receive/`, `sales/`, `recommend/`, `app/api/recommendations/`, `lib/ai/`(아래 성윤우 파일 제외), `lib/stock/status.ts`, `lib/stock/order.ts`, `components/ui/`, `components/common/`, `actions/menus.ts` |
| 임지섭 | `supabase/migrations/`, `types/database.ts`, `types/contracts.ts`, `lib/stock/`(김형균 파일 제외), `lib/queries/`, `lib/supabase/`, `lib/result.ts`, `lib/date.ts`, `actions/`(menus.ts 제외) |
| 성윤우 | `app/(main)/ingredients/`, `menus/`, `waste/`, `orders/`, 각 화면 전용 `components/<화면>/`, `lib/ai/prompts/`, `lib/ai/__fixtures__/`, `supabase/seed.sql`, `tests/e2e/`, `docs/logs/ai-usage.md` |

- `components/ui`(shadcn)는 2.4에서 필요한 것을 한 번에 추가한다. 이후 추가가 필요하면 김형균에게 요청한다.
- `types/database.ts`는 마이그레이션 후 임지섭만 다시 생성한다.
- **골격 예외 (2.4):** 로그인·매장 생성이 동작하도록 2.4에서 `lib/supabase/*`, `lib/result.ts`, `lib/queries/store.ts`, `actions/store.ts`, `supabase/migrations/0000_stores.sql`과 각 화면의 자리표시 `page.tsx`를 처음 만들었다. 머지 후에는 위 표의 소유자가 맡는다. 2.7은 `0001_init`부터 이어서 쓰고 `stores`·`is_my_store`는 다시 만들지 않는다.

### 3.2 계약 먼저 (2.10)

1. 11주 목요일(11/05)까지 임지섭이 `types/contracts.ts`와 서버 액션 **stub**(시그니처는 최종, 본문은 고정값 반환)을 main에 올린다.
2. 화면 담당(a 작업)은 stub을 호출하며 화면을 완성한다. 서버 완성을 기다리지 않는다.
3. 서버 담당(b 작업)은 같은 시그니처를 유지한 채 본문만 실제 구현으로 바꾼다. 시그니처를 바꿔야 하면 화면 담당과 합의하고 `08_API_SPEC.md`를 먼저 고친다.

### 3.3 브랜치·PR

- 브랜치는 작업 ID 단위: `feat/3.1a-ingredients-ui`, `feat/3.1b-ingredients-server`
- PR은 하루 분량 이하로 작게, 매일 main을 rebase한다.
- 성윤우 PR은 1.6 리뷰어가 승인해야 머지한다. 나머지는 리뷰 1명.
