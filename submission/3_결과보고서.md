### 3.3 설계 핵심

1. **재고를 입고 묶음 단위로 관리** — 묶음마다 기한, 차감은 기한 빠른 묶음부터(BR-02). 재료 총량만 두면 기한 추적과 FEFO가 불가능하다 (ADR 3).
2. **계산은 TypeScript, 반영은 DB 함수(RPC)** — 어떤 묶음에서 얼마를 뺄지는 `lib/stock` 순수 함수가 계산하고, RPC 하나가 한 트랜잭션으로 묶음을 잠그고 잔량을 다시 확인해 반영한다. 계산은 DB 없이 테스트하고, 반영은 부분 실패가 없다 (ADR 4).
3. **재고·판매·AI 사용 기록은 RPC로만 변경, 이력은 추가만** — REST 직접 쓰기는 DB 정책으로 막았다(0008·0009).
4. **AI는 제안만** — AI 출력은 Zod 스키마로 강제하고 서버가 재검증·재계산하며, 사용자가 확인해야만 저장된다 (BR-04).
5. **매장 격리** — 모든 테이블 RLS, 서버는 화면이 보낸 매장 ID를 믿지 않고 세션에서 구한다.
