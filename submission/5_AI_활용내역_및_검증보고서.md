> 융합SW모델설계 PBL ⑧ 최종 산출물 · 팀 재고콕 (김형균·임지섭·성윤우) · 작성 성윤우·김형균 · 목차: 테스트 계획 12.3
> 기준: 11/24 기능 동결 시점 저장소, AI 활용 로그(제출본 `5-1_AI_활용_로그.md`), 테스트 결과(`4_테스트_결과표.md`). 실제 AI 20회 평가(`pnpm eval:recommend --live`)는 실행하지 못해 해당 수치는 "미실행"으로 적었다. 추정치는 넣지 않았다.

## 1. 개요

재고콕은 AI를 두 곳에서 썼다.

| 구분 | 내용 | 검증 대상 |
|---|---|---|
| 서비스의 AI 기능 | **메뉴 추천** (F-04, 필수): 재고·기한·메뉴·판매 데이터를 보고 오늘 밀 기존 메뉴와 신규 특선을 제안. **보관일수 추천**(4.6, 확장): 재료 등록 때 기본 보관일수 제안. **명세서 인식**(4.7, 확장): 거래명세서 사진에서 품목·수량·금액 추출 → 확인 화면 → 입고 | 추천 결과가 실제 재고와 맞는지, 실패해도 서비스가 동작하는지, 추출 결과가 사용자 확인 없이 저장되지 않는지 |
| 개발 과정의 AI 도구 | Claude Code(김형균·임지섭), Codex(성윤우)로 문서·코드·테스트·리뷰 초안 작성 | AI 산출물을 사람이 어떻게 검증하고 채택·수정·폐기했는지 |

**원칙:** AI는 제안만 한다. 날짜·수량·원가·재고 판정은 코드가 하고, AI 결과는 사용자가 확인해야만 저장된다 (SRS BR-04, `AGENTS.md` 규칙 1·2).

## 2. 검증 장치 (서비스 AI)

```
재고 DB ─▶ ① 입력 구성 (Strategy가 재료 우선순위, 경과 묶음 제외)
        ─▶ ② AI 호출 (AiClient → GeminiAdapter, 45초 제한)
        ─▶ ③ 스키마 검증 (Zod, 틀리면 1회 재시도)
        ─▶ ④ 후처리: 없는 메뉴 제외 · 재료 이름 매칭 · 재고 대조(보유/부족/미등록) · 원가·수량 서버 재계산
        ─▶ ⑤ 화면에 "AI 추천" 표시 → 사용자가 판매가·사용량 확인 후에만 특선 메뉴 저장
   실패 ─▶ 규칙 기반 대체: 임박(D-0~D-3) 재료가 든 기존 메뉴 (fallback 표시)
```

### 4.3 장애 대응 확인 (NFR-08)

- **지연:** 5.2 점검에서 AI 응답이 늦으면 규칙 기반 대체 전에 서버 함수가 60초 제한으로 끝나는 문제(이슈 #85)를 찾아, 재시도를 포함한 전체 생성 시간을 45초로 묶고 넘으면 대체로 넘어가게 고쳤다(#96). 느린 형식 오류 뒤 대체 추천 회귀 검사 포함 (4.4d, `docs/logs/ai-timeout-20261124/`).
- **거부:** 11/17 새 API 키로 처음 호출했을 때 Gemini가 `403 PERMISSION_DENIED`("이 프로젝트는 무료 등급을 쓸 수 없음")를 돌려줬다. 어댑터가 이를 `AI_FAILED`로 바꿨고, 추천은 규칙 기반 대체로 넘어가 오류 화면 없이 동작했다. 몇 분 뒤 같은 키로 정상 응답을 받았다(새 프로젝트의 무료 등급 활성화 지연으로 추정, 원인 미확정).

### 7.2 작업 방식과 검증

- 사람이 범위·우선순위·설계 방향을 정해 요청하고, AI가 초안을 만들면 사람이 검토해 채택·수정·폐기했다. 저장소 규칙(`AGENTS.md`)으로 AI가 지킬 범위(계산은 `lib/stock`, 계약 먼저, 소유자만 수정, 비밀 파일 금지 등)를 정했다.
- 모든 AI 산출물은 PR 리뷰 1명 이상과 CI(lint·typecheck·test·DB 테스트·build)를 통과해야 병합했다.
- 검증 방법: 손계산 대조, 로컬 Supabase 실제 실행, 375×812 브라우저 확인, 독립 QA(별도 에이전트 검토 후 사람이 판정), 문서·PR 기록 대조.

### 7.3 폐기·수정한 AI 제안 (대표 사례)

| 사례 | 처리 |
|---|---|
| 안전재고 추천 기능, Observer 패턴 제안 | 발주 목록과 겹치고 통지 대상이 없어 폐기 |
| AI SDK `generateObject` 사용 설계 | SDK 7에서 폐기 예정이라 `generateText` + `Output.object()`로 교체 |
| AI가 기존 테스트 파일을 새 파일로 덮어씀 | 커밋 직후 발견해 원래 내용 복구 후 새 테스트만 덧붙임 |
| 리뷰 에이전트의 사실과 다른 지적 | 로컬 실행으로 확인해 제외 |
| 실제 AI 확인 테스트가 전부 실패해도 통과하게 작성됨 | AI가 스스로 발견해 실패하도록 수정 후 재실행 |
| 클라우드 데모 DB로 화면 테스트 | 테스트 데이터가 남는 문제로 로컬 Supabase로 변경 |

## 8. 한계와 향후 과제

- 실제 AI 20회 평가(`--live`)를 실행하지 못해 NFR-03(재고 대조 100%)은 표본 1건 확인에 그쳤다. 평가 도구는 준비돼 있어 키가 있는 환경에서 바로 실행할 수 있다.
- 무료 등급은 하루 요청 한도가 작고 입력이 Google 서비스 개선에 쓰일 수 있다. 추천 입력에는 식자재·메뉴만 있고 개인정보는 없다. 실제 서비스는 유료 등급이 필요하다.
- AI가 제안한 판매가·조리 단계의 품질(맛·실현 가능성)은 자동으로 검증할 수 없어 사용자 확인에 맡겼다.
