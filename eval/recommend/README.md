# 4.4 추천 평가

`10_TEST_PLAN.md` 7장용 실행 도구다. 기본 실행·`--help`·`--plan`은 모델을 호출하지 않는다. 앱의 SDK·모델·프롬프트·후처리는 바꾸지 않는다. Node 22.15 이상이 필요하며, Node의 기본 TS 변환·모듈 훅으로 프로젝트 별칭을 해석하므로 새 의존성은 추가하지 않는다.

## 실행

```powershell
pnpm test:eval
pnpm eval:recommend --plan
$evalCommit = git rev-parse HEAD
pnpm eval:recommend --prepare-only --source-commit $evalCommit
pnpm eval:recommend --live --source-commit $evalCommit
```

`$evalCommit`은 실행할 체크아웃의 실제 HEAD다. 기록된 과거 측정 SHA를 새 실행의 인자로 복사하지 않는다. Git 원본에서는 실제 HEAD와 커밋을 대조하고 작업 상태를 기록한다. Git 없는 실행 복사본은 `pnpm test:source --source $evalCommit --output test-results/source.json`을 원본에서 실행한 뒤, 평가에 `--source-manifest`로 그 파일을 지정한다. 앱 전체·후처리·전략·클라이언트·평가 도구의 파일 집합과 해시가 같아야 실행한다. 이는 깨끗한 커밋이라는 주장이 아니며 미커밋 변경 목록도 함께 보관한다.

`SUPABASE_TEST_URL`, `SUPABASE_TEST_ANON_KEY`와 선택한 공급자의 키는 실행 프로세스 환경에 설정한다. `.env`는 자동으로 읽거나 출력하지 않는다. 기본 공급자는 Gemini이며 모델 ID는 기존 `lib/ai/adapters`만 사용한다. pnpm 명령은 위처럼 `--` 구분자 없이 쓴다. npm의 `npm run eval:recommend -- --plan` 형식과 호환되도록 선행 구분자 하나도 처리한다.

`--live`는 20회 요청을 고정한다. Adapter 내부 재시도는 기존 정책을 따르며, 부족한 표본을 채우려고 자동으로 추가 호출하지 않는다. 결과가 전부 대체이거나 실제 AI 성공 20건·시나리오/기준 분포가 부족하면 NFR-03은 BLOCKED다. 키 값·세션·비밀번호는 결과에 쓰지 않는다.

## 데이터와 정답

- 격리 로컬 Supabase에 시나리오별 새 일반 사용자·매장을 만든다. 클라우드 URL·service role은 거부한다.
- 매장마다 재료 30종·메뉴 15개·판매 14일. 과거 판매는 기한 안의 이력용 묶음에서 FEFO 순수 함수와 RPC로 실제 차감한다. 평가 당일에는 이 묶음들이 경과해 정답에서 빠진다.
- 평가용 새 묶음을 추가해 정상 혼합·경과만·부족·미등록 유도·단가/인기 순위 차이 5종을 만든다. 미등록 유도는 등록되지 않은 바질을 메뉴 이름에 언급하며 실제 미등록 언급 발생 자체를 보장하지 않는다.
- 새 묶음의 사전 정한 수량과 DB `get_ingredient_stock` 반환을 교차 대조하고, 실제 DB 묶음의 수량·기한으로 가용량과 임박 여부도 확인한다. 실제 AI 출력이나 검증 대상 후처리로 정답을 만들지 않는다. 날짜·재고 판정은 기존 `lib/stock` 함수를 쓴다.
- 각 시나리오에 expiry 2·cost 1·popularity 1, 총 10/5/5. 과거 고정 날짜 시드를 현재 재고로 간주하지 않는다.

## 증거와 판정 한계

`eval/results/`의 새 회차 폴더에 소스 해시·Git 상태, 실행 계획, DB 정답, 요청 프롬프트, 스키마를 통과한 후처리 전 출력, 후처리 결과, 오류·대체 분류·지연과 최종 지표를 보존한다. 기존 회차는 덮어쓰지 않는다. 표본은 시작·모델 요청·원시 출력 수신·최종 응답 때 순서대로 체크포인트를 저장한다. 최종 응답을 저장한 다음 재고를 재조회하므로 이 조회가 실패해도 유료 호출 증거가 남는다. 무결성 확인 실패·재고 변화·KST 변경 때 추가 호출을 중단하고 `run-state.json`의 중단 이유와 부분 `summary.json`을 보존한다. 예외는 단계·유형·코드를 남기고 민감 값이 섞일 수 있는 원문은 기록하지 않는다.

상태 일치율과 상태·필드 전체 일치율, 불일치 건수, 서버 집계 불일치를 함께 보고한다. 기존 메뉴의 서버 레시피 재료와 AI 아이디어 재료도 나누어 집계한다. 정확한 20개 요청의 중복·누락을 검사하고, 잘못된 지연 값이 있어도 표본은 유지하되 P95는 산출 불가로 표시한다.

임박 활용률은 계획 7.2의 전체 expiry 성공 응답 분모를 유지한다. 경과만 있는 시나리오 2건에는 활용 기회가 없어 현재 설계의 상한은 80%다. 기회 없는 건수·상한·임박 재료 보유 표본의 보조율을 함께 기록한다. 공식 분모 변경과 AI 아이디어만을 품질 분모로 삼는 방안은 성윤우·김형균·임지섭 합의 대기이며, 보조율로 기존 목표의 PASS를 대신하지 않는다.

이 도구는 Route Handler가 쓰는 `createRecommendation` 본문을 실행한다. HTTP·인증 오버헤드, Adapter 내부 실패 HTTP 원문·재시도 횟수는 관측 범위 밖이다. 본문 P95를 HTTP 전체 NFR-06 통과로 표현하지 않는다. 실제 UI·인증·사용성·실기기 검증도 별도다.

`pnpm test:eval`은 평가 집계기의 모의 데이터 회귀 검사이며 실제 모델 품질 표본에 포함하지 않는다.
