## ✨ 주요 기능

| 기능 | 설명 |
|---|---|
| 📄 **명세서 사진 입고** | 거래명세서를 찍으면 AI가 품목·수량·단가를 읽고, 매장에 등록된 재료와 자동으로 연결합니다. 사장님은 확인 화면에서 확인만 합니다. |
| ▮▯ **바코드 입고** | 포장 제품 바코드를 스캔하면 식약처 공공 API로 제품을 조회합니다. 한 번 연결한 바코드는 다음부터 바로 인식됩니다. |
| 📅 **기한 자동 계산** | 라벨의 소비기한·제조일·산란일, 재료별 보관일수를 조합해 입고 묶음마다 기한을 계산합니다. |
| 🧾 **판매 연동 차감** | 하루 판매량만 입력하면 레시피 기준으로 **기한이 빠른 묶음부터** 자동 차감합니다. |
| ⚠️ **대시보드** | 기한 임박·재고 부족·주간 폐기 금액을 첫 화면에서 보여줍니다. |
| ✨ **AI 메뉴 추천** | 임박 재료를 소진할 기존 메뉴와 새 특선 메뉴, 예상 원가를 제안합니다. |

## 🛠 기술 스택

| 영역 | 기술 | 선택 이유 |
|---|---|---|
| Frontend·Server | Next.js (App Router), TypeScript | 3명·5주 조건에서 프론트·서버를 하나의 저장소와 배포로 운영 |

## 🔥 기술적 도전과 해결

<!-- 실제로 겪은 문제·수치로 업데이트할 것. 면접에서 가장 많이 질문받는 부분 -->

### 1. AI가 틀린 값을 재고에 넣지 않게 하기
- **문제:** AI가 수량을 잘못 읽거나 존재하지 않는 재료로 메뉴를 추천할 수 있음
- **해결:** 세 단계로 막았습니다.
  - ① AI 출력을 Zod 스키마로 강제
  - ② 서버가 재료 ID·재고량·원가를 다시 검증하고 직접 계산
  - ③ 사용자 확인 없이는 DB에 반영하지 않음
- **결과:** 추천 중 검증을 통과한 비율 `{__}`%, 잘못된 입고 `{__}`건

### 2. 동시에 판매를 입력해도 재고가 꼬이지 않게 하기
- **문제:** Supabase 클라이언트는 여러 쿼리를 하나의 트랜잭션으로 묶을 수 없음
- **해결:** 역할을 둘로 나눴습니다.
  - **차감 계획**은 TypeScript 순수 함수로 만들어 테스트
  - **적용**은 Postgres 함수(RPC) 하나에서 처리: 행 잠금(`FOR UPDATE`) → 잔량 재검증 → 반영
  - 계획한 뒤 재고가 바뀌었으면 거부하고 다시 계획
- **결과:** 동시 차감 테스트에서 음수 재고 0건, 핵심 로직 테스트 커버리지 `{__}`%

### 3. 바코드로는 유통기한을 알 수 없다
- **문제:** 바코드는 제품 단위 번호라서 같은 제품이면 모든 포장의 번호가 같음. 개별 포장의 날짜는 알 수 없음
- **해결:** 날짜 출처에 우선순위를 두고, 사용한 출처를 화면에 함께 표시했습니다.
  - 우선순위: 직접 입력 > 라벨 소비기한 > 제조일·산란일 + 기간 > 입고일 + 보관일수
  - "12개월" 같은 월 단위 기간은 일수로 바꾸지 않고 달력 기준으로 계산(말일 보정)
- **결과:** 실제 매장 바코드 조회율 `{__}`%

## 🤝 협업 방식

- **문서 우선:** 개발 전에 PRD → SRS → API·DB 명세를 작성하고, 요구사항 ID로 코드·테스트까지 추적 ([추적표](docs/03_SRS.md))
- **코드 리뷰:** main 직접 push 금지, 모든 PR은 리뷰 1명 이상 승인 후 머지
- **일정 관리:** 주간 마일스톤, 일정이 밀릴 때 뺄 기능 순서(컷라인)를 미리 합의 ([WBS](docs/04_WBS.md))
- **AI 코딩 도구 활용:** Claude Code·Codex에 프로젝트 규칙 파일([AGENTS.md](AGENTS.md))을 제공하고, 작업 단위·완료 조건을 정해 결과물을 사람이 검토
